# 故障排查

## 服务无法启动

- 确认 Python 为 3.11+：`python --version`。
- 重新安装：`python -m pip install -e '.[test]'`。
- 端口被占用时设置 `AGENT_PORT` 为其他本机端口，并同步修改扩展来源后重新加载。
- 查看终端异常类型；不要把包含个人信息或密钥的完整日志发到公开 Issue。

## `llm_configured=false`

这不是健康失败。需要自然语言 Agent 时，确认 `.env.local` 位于项目根目录，且 `LLM_API_KEY`、`LLM_MODEL` 非空。OpenAI 兼容服务还需正确的 `LLM_BASE_URL`。修改后重启进程。

模型超时可调整 `REQUEST_TIMEOUT_SECONDS` 和 `AI_RANKING_TIMEOUT_SECONDS`，但不要因此绕过 Pydantic 校验或副作用闸门。

## 职位搜索为零或 503

- 外部公开职位源可能超时、限流或没有对应关键词。
- 改用更具体或中英文组合方向，确认 Base 没有过度限制。
- 企业官方目录仍可工作，但“入口存在”不代表当前有开放岗位。
- 不要通过绕过登录、验证码或 robots/站点条款来补足数据。

## 扩展没有接管按钮或无响应

1. 确认扩展版本为 `0.6.0`。
2. 在扩展管理页点击“重新加载”，再强制刷新工作台。
3. 确认服务地址与 `manifest.json`、`bridge.js` 中的本机 Origin 一致。
4. 第一次访问企业站点时批准当前单一域名权限。
5. 查看扩展 service worker 和侧边栏 Console，提交 Issue 时仅提供脱敏错误摘要。

## 合成档案在官网停止

这是预期行为。合成档案只允许只读核岗和导航到登录/申请边界，不允许手机号、验证码、填表或提交。完整自动化只能在 `/browser-fixture` 本机演练页测试。

## 验证码无法继续

- 扩展不会读取短信，必须由用户手动输入。
- 存在 CAPTCHA 时先在官网人工完成，再重新发起；扩展不会绕过。
- 协议勾选和逐岗位提交确认是两个独立授权。
- 验证码只在当前侧栏内存中；关闭弹窗或发生跳转后需要重新输入。

## 填表计划被拒绝

- 页面 DOM 在扫描后变化，字段签名不一致；重新扫描。
- 有必填字段无法从简历映射；回工作台补齐事实。
- 字段属于密码、证件、人口统计、详细地址、薪资、文件或同意项；需要用户在官网人工处理。
- 页面存在已有值，扩展按设计不覆盖。

## 不能最终提交

依次检查：当前是否合成档案、是否逐岗位授权、是否有 CAPTCHA、是否有附件或缺失必填项、是否有未确认声明、最终按钮是否唯一明确。不要为了“通过”而修改按钮识别规则或关闭安全检查。

## Docker 健康检查失败

```bash
docker compose ps
docker compose logs --tail=100 resume-agent
```

确认 `.env.server` 权限和变量名正确、宿主机回环端口可用、磁盘有空间。日志不得上传到公共 Issue，除非已去除简历、请求正文、主机信息和凭据。
