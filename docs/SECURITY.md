# 安全与隐私手册

## 适用范围

本文描述当前 Alpha 版本的安全边界。漏洞披露流程见仓库根目录 [SECURITY.md](../SECURITY.md)。

## 数据分类

| 级别 | 示例 | 处理规则 |
|---|---|---|
| 公开 | 职位标题、公司、公开招聘链接 | 可用于搜索和匹配，仍需记录来源 |
| 简历事实 | 教育、工作、项目、技能 | 仅在当前会话使用；模型只接收完成任务所需的去标识内容 |
| 直接标识 | 姓名、电话、邮箱、详细地址 | 不发送 LLM；不写运行日志；只在本地绑定到确定字段 |
| 高敏感 | 身份证、密码、验证码、人口统计、银行卡 | 普通填表禁止；验证码只存在扩展侧栏短期 DOM 状态 |
| 凭据 | LLM API Key、部署密钥、Cookie | 只由环境或密钥管理器注入，绝不进入仓库和模型 |

## 浏览器权限

扩展固定权限只有 `activeTab`、`scripting`、`storage` 和 `sidePanel`。招聘网站权限通过 `optional_host_permissions` 在当前单一域名首次使用时请求。扩展不申请 `debugger`、`cookies`、`history`、`downloads`、剪贴板或通知权限。

扩展持久存储只保存本机会话 ID；企业接管元数据使用会话级存储；手机号不进入扩展存储，验证码不离开当前侧栏 DOM。

## LLM 隔离

- 简历审核在构造模型上下文前删除姓名、电话、邮箱等直接标识。
- 浏览器字段语义映射只提供字段标签、类型、选项和可用简历字段名。
- LLM 输出必须通过 Pydantic 模型和确定性规则再次校验。
- 未配置、超时或输出无效时安全降级，不因此放宽提交闸门。

## 外部副作用

服务端批量发送永远拒绝。浏览器提交只有同时满足以下条件才可触发：

1. 用户已确认当前企业和具体岗位；
2. 页面与预检时字段签名一致；
3. 无 CAPTCHA、附件、缺失必填字段或未确认声明；
4. 只有一个明确且可用的最终申请按钮；
5. 当前不是合成档案官网预演；
6. 用户单独授权最终提交。

触发后必须等待官网回执。网络跳转、按钮消失或扩展提示不能单独证明成功。

## 部署边界

默认应用没有账号认证、多租户隔离、持久数据库、速率限制或生产审计系统。因此：

- 推荐只监听 `127.0.0.1`；远程使用通过 SSH 隧道访问。
- 不要直接公开 `18010`，也不要仅靠一个临时 HTTPS 隧道承载真实简历。
- 公网部署前必须增加认证、授权、CSRF、限流、持久加密密钥、数据删除和备份恢复。
- 反向代理必须限制请求体、设置 TLS 和安全响应头，并避免记录请求正文。

## 仓库与日志卫生

- `.env.local`、`.env.server`、`*.pem`、日志、原始证据、发布包和内部账本已被 Git 忽略。
- `python scripts/check_public_release.py` 会检查已跟踪文件中的常见密钥形态、私钥头和本机绝对路径。
- Issue、PR、截图和测试记录只能使用合成资料。
- 若密钥曾进入 Git 历史，删除文件不够；必须先吊销密钥，再清理历史并通知维护者。

## 已知限制

- 招聘页面变化可能导致识别失败；失败应停下，不应尝试更激进的点击。
- 通用字段规则不能覆盖所有国家、专业和门户；高敏感字段默认拒绝。
- 内存保险箱只降低误暴露，不提供跨进程生产级密钥保护。
- 网站条款和当地法律可能限制自动化；部署者和使用者需自行核验。
